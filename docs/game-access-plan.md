# 아발론·주루마블 서비스 기획서

루트의 `avalon-boardgame-handoff.zip`에서 아발론과 주루마블을 이관한다. 기존 보드게임 서비스의 제품명은 **주루마블**로 변경한다. 두 서비스의 소개와 탐색 화면은 비로그인 사용자에게도 열어두며, 서비스별로 행동 권한을 적용한다.

## 공통 로그인과 프로필

- 카카오·구글 로그인을 제공한다. 공통 로그인 모달은 모든 페이지에서 열 수 있다. 로그인 완료 후에는 모달을 열었던 화면으로 돌아가고, 입력해 둔 아발론 방 코드를 복원한다.
- 계정 식별과 권한 판정에는 Supabase Auth UUID를 사용한다. 소유자, 공유 대상, 편집 잠금의 계정 ID는 DB의 `uuid` 타입으로 저장한다.
- 첫 로그인 후 내 정보 등록 모달에서 닉네임과 실명을 등록한다. 닉네임은 1~24자로 중복을 허용하지 않으며, 실명은 1~80자로 저장한다. 헤더의 유저 아이콘에서 두 항목을 수정하고 로그아웃할 수 있다. 기존 사용자도 최초 한 번 정보를 등록한다.
- 실명은 아발론의 실명 사용 방과 주루마블의 초대 대상 조회에 사용한다. 일반 프로필과 공개 목록에는 닉네임을 표시한다.
- `super_admin`은 두 서비스의 모든 접근·관리 권한을 갖는다. 아발론의 비공개 방에 코드 없이 접근할 수 있고, 방장과 주루마블 소유자의 관리 기능도 사용할 수 있다. 아발론의 역할 공개 범위와 투표·원정 행동에는 참가자와 게임 단계에 따른 게임 규칙을 적용한다.

## 주루마블

### 공개와 공유 권한

공개 보드는 비로그인 상태에서도 열고 실행할 수 있다. 주사위, 말 위치, 턴, 점수는 기존처럼 실행한 브라우저에 저장한다.

참가 팀은 1~4팀으로 조절하며, 팀 수는 브라우저에 보드별로 저장한다. 기본값은 4팀이다. 팀 수를 줄였다가 늘리면 해당 팀의 이름과 말 위치를 복원한다.

| 권한 | 공개 보드 열기·실행 | 권한이 부여된 비공개 보드 열기·실행 | 해당 보드 편집 | 해당 보드 공개 설정·공유 관리 |
| --- | --- | --- | --- | --- |
| 방문자 또는 개별 권한이 없는 사용자 | 가능 | — | — | — |
| 뷰어 | 가능 | 가능 | — | — |
| 편집자 | 가능 | 가능 | 가능 | — |
| 소유자 | 가능 | 가능 | 가능 | 가능 |
| `super_admin` | 가능 | 모든 보드 | 모든 보드 | 모든 보드 |

- 보드 소유자와 `super_admin`은 보드를 전체 공개하거나 비공개로 전환하고, 개별 사용자에게 뷰어·편집자 권한을 부여하거나 회수할 수 있다. 공개 여부를 바꿔도 개별 권한은 유지한다.
- 로그인한 일반 사용자는 주루마블을 최대 2개까지 소유할 수 있다. 공유받은 보드는 이 수에 포함되지 않으며, 본인 보드를 삭제하면 다시 생성할 수 있다. `super_admin`은 개수 제한 없이 생성하고 모든 보드를 수정·삭제할 수 있다.
- 목록 상단에서 `전체`, `비공개`, `내가 만든 게임` 배지 중 하나를 선택한다. 전체에는 접근 가능한 모든 보드, 비공개에는 그중 비공개 보드, 내가 만든 게임에는 본인이 소유한 보드만 표시한다. 관리자에게도 같은 소유자 기준을 적용한다.
- 비공개 보드의 목록·상세 조회와 편집, 공유 관리는 서버와 DB에서 권한을 검증한다.

### 초대

보드 소유자와 `super_admin`이 초대할 수 있다. 닉네임, 실명, 이메일로 대상을 찾을 수 있으며 실명·이메일 초대로 대상을 식별하면 상대의 수락 절차 없이 편집 권한을 즉시 부여한다.

| 입력 방식 | 처리 | 초대자가 확인할 수 있는 정보 |
| --- | --- | --- |
| 닉네임 | 자동 생성 닉네임 전체가 일치하는 대상을 선택하고 권한을 부여한다. | 일치한 계정의 닉네임 |
| 이메일 | 이메일 전체가 일치하는 계정에 편집 권한을 즉시 부여한다. | 요청 접수 결과 |
| 실명 | 실명 전체가 일치하고 실명으로 초대받기를 허용한 계정이 한 명일 때 편집 권한을 즉시 부여한다. | 요청 접수 결과 |

- 실명·이메일 요청은 계정 일치 여부와 관계없이 `요청을 처리했습니다`로 표시한다. 실명으로 대상을 특정하기 어려운 경우를 위해 이메일이나 닉네임으로도 초대할 수 있다는 안내를 초대 화면에 항상 표시한다.
- 실명·이메일 요청으로 연결된 계정의 닉네임은 해당 요청의 공유 목록이나 처리 결과에 표시하지 않는다. 요청 시각과 부여 권한을 기준으로 소유자가 권한을 회수할 수 있게 한다.

## 아발론

### 방 생성과 설정

- 로그인한 사용자가 `방 만들기`를 누르면 제목 입력란, `비공개` 토글, `실명 사용` 토글, `생성` 버튼이 있는 모달을 연다. 제목의 플레이스홀더는 `(이름)의 게임`으로 표시하고, 이름에는 계정 닉네임을 사용한다. 제목을 비워 두거나 공백만 입력하면 플레이스홀더와 같은 제목으로 생성한다.
- 방장과 `super_admin`은 대기실의 별도 방 설정 모달에서 방 생성 후에도 `실명 사용` 설정을 바꿀 수 있다. 실명 사용의 기본값은 꺼짐이다. 실명 사용 방에서는 대기실, 플레이 화면, 종료 화면에 실명을 사용한다. 공개 방 목록에는 `실명 사용` 표시를 붙이고 참가자의 실명은 표시하지 않는다.
- 공개 방 대기실의 `비공개로 전환` 버튼은 방장과 `super_admin`에게 표시한다. 전환하면 공개 목록에서 방이 빠지며, 기존 참가자는 남는다. 방장의 기존 추방 기능을 유지한다.
- 아발론에 참가하거나 플레이하려면 로그인해야 한다. 기존 게임 진행을 유지하며 채팅 기능은 추가하지 않는다.

### 비공개 방 코드

- 처음부터 비공개로 만든 방과 비공개로 전환한 방은 대기실에 코드와 `코드 복사` 버튼을 표시한다.
- 대기실 입장 전 화면의 최상단에 `비공개 게임 입장` 섹션을 제공한다. 코드 입력 시 앞뒤 공백과 대소문자 차이를 허용한다.
- 방 코드는 대기실에서 신규 입장에 사용할 수 있다. 게임이 시작된 뒤에는 기존 참가자가 재접속할 수 있다.

### 실명 사용 확인

- 공개 실명 사용 방에 들어가기 전에 `이 방에서는 참가자에게 내 실명이 표시됩니다`라는 확인 모달을 띄운다. 사용자가 확인하면 입장한다.
- 확인 모달의 `다음부턴 묻지 않기` 설정은 계정별로 브라우저 `localStorage`에 저장한다. 같은 계정과 브라우저에서 이후 공개 실명 사용 방에 입장할 때 적용한다.
- 비공개 방에서는 확인 모달을 띄우지 않는다. 실명 사용 방인 경우 입장 후 대기실에 해당 설정을 표시한다.
- 공개 대기실에서 실명 사용을 켜면 기존 참가자에게도 같은 확인 절차를 적용한다. 확인을 마치기 전에는 해당 참가자의 실명을 공개하지 않는다.

## 구현 순서와 완료 기준

1. **이관과 공통 기반.** 기존 Next.js 프로젝트에 두 게임 화면과 로직을 통합한다. 공통 로그인 모달, OAuth 복귀, 프로필과 UUID 권한 모델을 연결한다. 아발론의 비공개 역할과 진행 상태는 서버에서 관리하고, 클라이언트에는 참가자에게 허용된 정보만 반환한다.
2. **주루마블.** 제품명, 보드 목록 필터, 공개 설정, 권한별 편집, 즉시 초대와 회수를 구현한다. 비로그인 공개 보드 실행, 권한 없는 비공개 보드 조회 거부, 뷰어의 편집 거부, 편집자의 공유 관리 거부를 확인한다. 실명·이메일 초대의 즉시 반영과 초대 대상의 식별 정보 비공개를 함께 확인한다.
3. **아발론.** 방 생성과 설정 모달, 비공개 전환, 코드 입장, 실명 사용 확인을 구현한다. 제목 기본값, 전환 후 기존 참가자 유지, 추방, 로그인 후 코드 복원, 게임 시작 후 신규 입장과 재접속 조건을 확인한다. 공개·비공개 방의 실명 확인 동작과 `super_admin` 권한을 확인한다.

## 남은 결정

- 실명을 최초 로그인 때 받는 방식이 제안되어 있다. 입력을 필수로 할지, 실명 사용 방을 선택할 때만 요청할지는 정해야 한다.
- 아발론 전적·랭킹과 진행 중인 방 정보의 비로그인 공개 범위는 정해야 한다.
